# VEY RASHA — Production Deployment Guide

This guide covers deploying the **VEY RASHA** boutique website and backend API using:

- **GitHub** for source code
- **GitHub Actions + GitHub Pages** for the frontend storefront
- **Render** for the Node.js + Express + WebSocket backend API

> **Important Note on Persistence & Supabase:** Supabase is **not** currently configured in this codebase. At present, the backend persists catalog state, customer order requests, notifications, and two-device owner security records in `data/boutique-store.json`. On Render's free ephemeral filesystem, this file resets whenever the service restarts or redeploys. For durable production storage without migrating to a database yet, upgrade to a paid Render plan with a Persistent Disk mounted at `/opt/render/project/src/data`—or add Supabase/PostgreSQL in a future backend update.

---

## 1. Prerequisites

Before deploying, make sure you have:

1. A **GitHub account** and a repository containing this project pushed to the `main` branch.
2. A **Render account** connected to your GitHub account.
3. Three strong random secrets you generate privately (for example using a password manager or `openssl rand -hex 32`):
   - `OWNER_ENROLLMENT_CODE_1` (single-use secret code for Owner Phone 1, 10+ characters, no spaces)
   - `OWNER_ENROLLMENT_CODE_2` (single-use secret code for Owner Phone 2, 10+ characters, no spaces)
   - `OWNER_RECOVERY_SECRET` (emergency server recovery secret)

Never put these owner codes or `SESSION_SECRET` inside any `VITE_*` variable or commit them to GitHub.

---

## 2. Repository Structure & Build Summary

- **Frontend entry:** `index.html`, `src/main.tsx`, `vite.config.ts`
- **Frontend API config:** `src/config/api.ts` (reads `VITE_API_BASE_URL` and `VITE_BASE_PATH`)
- **Frontend build command:** `npm run build`
- **Frontend output directory:** `./dist` (automatically includes `dist/404.html` and `dist/src/assets/...`)
- **Backend entry:** `server.ts` (runs directly on Node.js >= 22.14.0 via `npm start`)
- **Backend health check:** `GET /health`
- **GitHub Pages workflow:** `.github/workflows/deploy.yml`
- **Render blueprint:** `render.yaml`

---

## 3. Deploy the Backend on Render First

Deploy the Render backend first so you have its live HTTPS URL before building the GitHub Pages frontend.

1. Log in to **Render** (`https://dashboard.render.com`).
2. Click **New +** → **Web Service** (or **New +** → **Blueprint** to use `render.yaml` directly).
3. Connect your GitHub repository.
4. Confirm these settings:
   - **Runtime:** `Node` (Node 22+ is requested via `package.json` `engines.node`)
   - **Build Command:** `npm ci`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/health`
5. Add these **Environment Variables** in Render:
   - `NODE_ENV` = `production`
   - `SESSION_SECRET` = *(auto-generated by Render or paste 64 random hex characters)*
   - `FRONTEND_URL` = your GitHub Pages origin **without a trailing slash or repository subpath**, e.g.:
     - If your site is `https://your-username.github.io/vey-rasha/`, set `FRONTEND_URL` to `https://your-username.github.io`
     - If you use a custom domain, you can comma-separate multiple origins: `https://your-username.github.io,https://www.veyrasha.com`
   - `OWNER_ENROLLMENT_CODE_1` = your private code for Phone 1
   - `OWNER_ENROLLMENT_CODE_2` = your private code for Phone 2
   - `OWNER_RECOVERY_SECRET` = your private emergency recovery secret
6. Deploy the service and wait until Render reports **Live**.
7. Copy your Render backend URL, for example:
   `https://vey-rasha-api.onrender.com`

## 4. Configure GitHub Repository Variables

Configure the public API URL in GitHub so GitHub Actions compiles it into the frontend bundle:

1. Open your repository on GitHub.
2. Go to **Settings** → **Secrets and variables** → **Actions** → **Variables** tab.
3. Click **New repository variable**:
   - **Name:** `VITE_API_BASE_URL`
   - **Value:** Your Render URL with **no trailing slash**, e.g. `https://vey-rasha-api.onrender.com`
4. Optional: `VITE_BASE_PATH`
   - `.github/workflows/deploy.yml` automatically sets `/<repo-name>/` for project Pages repositories (or `/` for `<username>.github.io` root repositories).
   - Only set a `VITE_BASE_PATH` repository variable if you attach a custom domain to GitHub Pages (in which case set `VITE_BASE_PATH` to `/`).

---

## 5. Enable GitHub Pages & Automatic Deployment

1. In your GitHub repository, open **Settings** → **Pages**.
2. Under **Build and deployment** → **Source**, select **GitHub Actions**.
3. Push a commit to `main` (or open **Actions** → **Deploy VEY RASHA Frontend to GitHub Pages** → **Run workflow**).
4. Once the workflow finishes, GitHub Actions will display the live GitHub Pages URL.

---

## 6. Post-Deployment Verification Checklist

Run these checks after both services are live:

1. **Backend health:** Open `https://<your-render-service>.onrender.com/health` in a browser and confirm `{ "status": "ok", ... }`.
2. **Storefront load:** Open your GitHub Pages URL and verify all product, collection, and editorial images load cleanly.
3. **Nested route refresh:** Navigate to **Explore**, **Wishlist**, **Cart**, or **Account**, then refresh the browser page. Confirm it renders the boutique view instead of a GitHub 404.
4. **Live customer order flow:** Add an item to your bag, submit a manual checkout order request, and verify you receive an Order Reference in **Pending Review** status.
5. **Private two-device owner access:** On Owner Phone 1, type `OWNER_ENROLLMENT_CODE_1` in the storefront search bar and submit. Verify the private Owner Workspace opens, orders sync in real time over WebSocket, and **Authorized Devices & Security** shows Slot 1 active (`keyBound: true`). Repeat once on Phone 2 with `OWNER_ENROLLMENT_CODE_2`.

---

## 7. Security Reminders

- Never add `OWNER_ENROLLMENT_CODE_1`, `OWNER_ENROLLMENT_CODE_2`, `OWNER_RECOVERY_SECRET`, or `SESSION_SECRET` to `.github/workflows/deploy.yml` or GitHub `VITE_*` variables.
- Keep `FRONTEND_URL` on Render restricted to your exact frontend origin(s) — never `*`.
- Cross-origin owner authentication uses `HttpOnly; Secure; SameSite=None; Partitioned` cookies over HTTPS alongside WebCrypto P-256 device-key signatures. Always access both GitHub Pages and Render over `https://`.

---

## 8. Owner Recovery on Render (If Both Phones Are Lost)

1. Open the Render Dashboard → your `vey-rasha-api` service → **Shell** (or send an authenticated `POST /api/owner/security/emergency-recover` request using `X-Owner-Recovery-Secret`).
2. In the Render Shell, run:
   ```bash
   npm run owner:recover
   ```
3. Re-enroll your new phone(s) from the boutique search bar.

---

## 9. Troubleshooting

- **Frontend says backend is unavailable / CORS errors in browser console:**
  - Verify `VITE_API_BASE_URL` in GitHub Actions Variables matches your exact Render HTTPS URL with no trailing slash, and re-run the GitHub Actions workflow.
  - Verify `FRONTEND_URL` on Render is set to `https://<your-username>.github.io` (origin only, no `/repo-name/` path and no trailing slash).
- **Render free tier takes 30–50 seconds on first load:**
  - Render Free Web Services spin down after 15 minutes of inactivity. Use the **Retry Connection** button in Checkout, Account, or Notifications once the backend wakes up.
- **Images break on GitHub Pages:**
  - Ensure `VITE_BASE_PATH` includes leading and trailing slashes (e.g. `/vey-rasha/`), or leave `VITE_BASE_PATH` unset so `.github/workflows/deploy.yml` auto-detects `/<repo>/`.
- **Owner dashboard does not stay signed in after refreshing on GitHub Pages:**
  - Confirm both frontend and backend are served over `https://` and that your browser does not block partitioned/third-party cookies for `https://<your-render-service>.onrender.com`, or use the native Capacitor Android app where the device token is stored in Android Keystore.
